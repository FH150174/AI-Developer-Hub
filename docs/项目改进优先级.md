## 01｜防止旧窗口覆盖项目列表

**场景。** 两个窗口都读到 `[A]`。窗口一添加 B 并保存；窗口二稍后添加 C，仍会用自己的 `[A, C]` 替换磁盘上的 `[A, B]`。B 的目录没有被删除，但列表项消失了。两次点击不必同时发生。

**修复前的依据（`82919c4`）。** `project/ProjectListView.java:54–56,443–449` 只在初始化时加载列表，保存时提交整份内存列表。`project/ProjectStore.java:50–65` 已用临时文件原子替换，这能防止写出半个 XML，不能判断另一窗口是否更新过文件。

**修复。** 添加、改名和删除都传入编辑前的快照。在独立的 `projects.xml.lock` 文件上取得写锁后，才重新读取列表、比较快照并原子替换 XML。列表已变化或写锁被占用时，本次修改不会写入；在 Projects 点击“重新加载列表”即可查看最新内容并重试。

**验收：**
- [x] 两个实例从 `[A]` 开始，先保存 B，再从旧窗口保存 C：第二次得到明确的冲突提示，磁盘仍为 `[A, B]`。重新加载后能保存为 `[A, B, C]`。
- [x] 在临时数据目录中让两个进程基于同一快照同时保存：不能出现双方都报告成功、最终却只有一份修改的情况。

**验证记录（2026-11-18）。** 修复前，`ProjectStoreTest` 的旧快照用例失败：第二次保存没有报告冲突。修复后该用例通过；`ProjectStoreConcurrencyTest` 用两个 JVM 验证只有一个能保存，磁盘内容与成功方一致。Windows 上运行 `mvn test`：270 项通过，0 失败、0 错误、0 跳过。

## 02｜让同一个 Windows 项目找回原有日志和 TODO

**场景。** 在大小写不敏感的 Windows 目录中，`D:\Work\Demo` 与 `D:\work\demo` 可指向同一项目。项目列表用 `Path.equals` 去重，而日志和 TODO 按路径字符串计算 SHA-256 文件名。移除后换一种拼写再添加，原 XML 可能仍在，界面却显示为空。

**修复前的依据（`2288543`）。** `project/ProjectList.java:11–18`、`notes/ProjectLogStore.java:86–94`、`todo/ProjectTodoStore.java:90–98`。当时的 `ProjectWorkflowIntegrationTest.java:54–62` 只验证了使用原拼写重新添加的情况。

**修复。** Notes 和 TODO 通过 `storage/ProjectHistoryFiles.java` 查找历史数据。新记录按磁盘上的目录拼写命名；遇到 v1.0 文件时，核对其 `project.path`、散列文件名和目录实际拼写。只找到一份就继续使用原文件；找到多份时，界面列出冲突文件，停止读写，供用户备份后核对。项目目录不存在时仍可按原键读取，不会猜测两种拼写指向同一目录。

**验收：**
- [x] 在大小写不敏感的 Windows 临时目录中，先保存一条日志和一个 TODO；移除列表项，以另一种大小写重新添加，重启后两条记录均可读。
- [x] 两个不同父目录下的同名项目仍然隔离；已存在两份历史数据时，任何一份都不会被静默覆盖。

**验证记录（2026-11-18）。** `ProjectHistoryPathTest` 用独立构造的 v1.0 XML 复现了两项失败：换拼写返回空列表、双份历史未报告冲突。修复后的 4 项回归测试通过，验证了旧文件可继续编辑、冲突原件字节不变、同名项目隔离及离线路径保护。Windows 上运行 `mvn test`：274 项通过，0 失败、0 错误、0 跳过。

## 03｜隐藏页面不主动扫描 Git 工作区

**场景。** 在 Projects 设置当前项目，会同时通知 Git 页和 Dashboard。两边的工作区控件都会调用 `readDetails`；Dashboard 只展示数量，却还会填充不显示的文件表格。之后进入 Git 页又会刷新。

**依据。** `navigation/MainView.java:80–89,147–151`、`dashboard/DashboardView.java:84–92`、`git/GitChangeCountView.java:51–57,72–86`。

**建议。** 先处理工作区查询：项目变化时让隐藏页的旧结果失效，进入页面后才读取；保留手动刷新和丢弃旧项目结果的逻辑。用查询次数验收，避免拿一次机器耗时作结论。

**验收：**
- [ ] 停留在 Projects 选择项目，两个隐藏页合计触发 **0 次**工作区状态查询；首次进入 Dashboard 触发 **1 次**，点击刷新后再触发 **1 次**。
- [ ] 快速从项目 A 切到 B，A 的迟到结果不会显示在 B 的页面上。Git 明细仍可查看，Dashboard 的变更数量仍正确。

## 04｜让路线图首页反映 v1.0 现状

**场景。** `README.md:29–40` 已提供 v1.0 安装说明，但 `docs/ROADMAP.md:3–20` 仍将初始化文档的 `TASK-001` 标为当前任务。`agent/ProjectContextService.java:17–23` 又会将路线图列入 Agent 的阅读清单。

**建议。** 只更新 `docs/ROADMAP.md`：把 TASK-001 放入历史里程碑，首页列出“v1.0 已交付”和“下一项待确认”，安装、测试和打包细节链接到现有文档。

**验收：**
- [ ] 对照 README 和路线图，两个入口给出一致的当前版本与交付状态。
- [ ] 新协作者能找到下一项候选任务；未批准的工作不会被写成版本承诺。
