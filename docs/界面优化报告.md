# AI Developer Hub 界面优化报告

**建议先改 Projects 页：让用户一眼分清“我选中了哪个项目”和“整个工作台正在使用哪个项目”。** 这两个状态决定终端会在哪里打开、日志会记到哪里，比调整配色更值得优先处理。

评审基线：`main` · `c856caa` · 2026-11-19。以下观察依据该版本的 JavaFX 源码及仓库内的 v1.0 深色主题截图；实施后的验收记录见第 4 节。

## 1. Projects：把操作对象放在操作旁边（优先）

[Projects 截图](images/projects.png)中，蓝色高亮表示表格选中行，顶栏显示当前项目。两者在截图里恰好相同，但实际可以不同：如果 A 是当前项目，单击 B 后，“用终端打开”会打开 B，而进入 Notes 新建日志仍会写到 A。表格只有名称、路径两列，没有独立的当前项目标记。

| 现状 | 建议 | 验收场景 |
| --- | --- | --- |
| 选中行和当前项目依赖两处信息判断。 | 给当前项目行加文字标记“当前”，保留高亮表示选中；在行操作旁显示“已选：B”。继续用“设为当前项目”显式切换。 | A 为当前项目时选中 B：A 仍标“当前”，B 高亮；点“用终端打开”进入 B，Notes 仍指向 A。点“设为当前项目”后，标记、顶栏和 Notes 才一起切到 B。 |
| 表格之前有四组按钮。添加、打开、诊断和移除并列；“删除项目”实际只移除列表项，容易让人担心磁盘目录也会被删除。 | 列表上方保留“添加项目”“设为当前项目”“打开方式 ▾”；将目录、终端和编辑器归入“打开方式”，改名与诊断归入“更多”。将删除入口写为“从列表移除”。正常时“重新加载列表”可放在“更多”，遇到加载失败或保存冲突时应直接可见。 | 默认窗口下无需滚过多排按钮即可看到项目行；只用键盘能打开选中项目的终端。移除 B 后，B 从列表消失，本地目录仍在；发生列表冲突时能从提示找到重新加载入口。 |

依据：[ProjectListView.java](../src/main/java/com/fhaicl/aidevhub/project/ProjectListView.java) 第 73–85、116–124、157–166、189–199、416–421 行；[MainView.java](../src/main/java/com/fhaicl/aidevhub/navigation/MainView.java) 第 80–90 行。当前源码已有“重新加载列表”，v1.0 截图未包含此按钮。

## 2. Notes / TODO：空列表只提示此刻能做的事（优先）

两个页面都已有读取状态和编辑权限判断；问题在于空列表里的固定提示。已选好项目但还没有记录时，Notes 仍会让用户“先在 Projects 选择当前项目”；TODO 在读取失败时，列表里还可能同时出现“添加任务”的引导。建议让占位内容跟随现有状态变化：

| 状态 | 建议展示 | 应可执行的操作 |
| --- | --- | --- |
| 未选项目 | “尚未选择当前项目。请到 Projects 选中项目，再点『设为当前项目』。” | 切到 Projects；不能新建记录。 |
| 正在读取 | “正在读取 A 的开发日志…”或“正在读取 A 的待办…” | 等待读取；不提前显示“暂无记录”。 |
| 读取成功，条数为零 | “A 还没有开发日志。记录今天的第一条进展吧。”TODO 对应提示添加第一项任务。 | 使用已有的“新建日志”或“添加任务”。 |
| 读取失败 | 保留具体原因和恢复指引；可重试的读取错误提供“重新读取”。历史文件冲突沿用已有的文件核对说明。 | 重试前保留错误信息，不能把失败显示成零条，也不能启用写入。 |

**验收：** 分别用未选项目、无记录项目、有记录项目和读取失败的项目进入两页。每次只看到与当前状态一致的引导；从 A 切到 B 后，不出现 A 的标题或正文。依据：[ProjectLogsView.java](../src/main/java/com/fhaicl/aidevhub/notes/ProjectLogsView.java) 第 55–57、98–142 行；[ProjectTodoView.java](../src/main/java/com/fhaicl/aidevhub/todo/ProjectTodoView.java) 第 50–55、98–135 行。

## 4. 实施后的共同验收条件

- **窗口与主题：** 从应用默认的 `960 × 640` 场景尺寸开始，在 Windows 100% 和 150% 缩放、深浅两种主题下复核。长项目名和路径不应挤走主按钮；若省略路径，仍应有查看完整路径的方式。
- **鼠标与键盘：** 分别用鼠标和 Tab、方向键、Enter 完成“选 B → 设为当前 → 新建第一条日志”。选中行、当前项目标记、键盘焦点三者应能分别辨认；菜单关闭后焦点应回到触发按钮。
- **视觉反馈：** [hub.css](../src/main/resources/com/fhaicl/aidevhub/ui/hub.css) 已有深浅主题、选中态和按钮焦点样式，可继续复用。当前 `.card:hover` 会给只读卡片也加上强调边框；建议仅让可操作元素在悬停时突出，避免静态指标看起来可以点击。

建议以第 1 节的 **A/B 双项目场景**作为第一项独立验收：只要用户能在按下按钮前说清“终端会打开 B，日志仍会记到 A”，这次改动就解决了最重要的问题。

### Windows 自动化验收记录（2026-11-22）

| JavaFX 输出缩放 | 在 Windows 仓库目录运行 | 结果 |
| --- | --- | --- |
| 100% | `mvn -o -Dglass.win.uiScale=1.0 test` | 全量 299 项通过，无跳过 |
| 150% | `mvn -o -Dglass.win.uiScale=1.5 -Dgroups=ui test` | 界面 26 项通过，无跳过 |

两档缩放均在 `960 × 640` 场景下验证了深浅主题。鼠标和键盘分别完成了“选 B → 设为当前 → 新建并保存第一条日志”：切换前 A 保留“当前”标记，关闭“更多”后焦点回到按钮，保存后从磁盘读回的日志仅属于 B。

长项目名不会撑宽日志编辑框或挤走保存按钮；被省略的路径可悬停查看，也可在 Projects 用键盘打开“更多 → 检查路径”。Dashboard 指标卡片悬停时外观不变，只有“统计说明”等可操作区域突出。以上为 JavaFX 窗口和输入事件的自动化结果；Windows 系统显示设置切换与实体键鼠的手感仍待人工复核。
